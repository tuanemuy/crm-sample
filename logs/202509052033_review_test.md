# テストコード レビューログ

実施日時: 2025-09-05 20:33
レビュー対象: テストコードの品質評価

## 改善点

### 1. テストケース名の日本語表記の統一性

**問題点**
- `createCustomer.test.ts`では一部のdescribe/itブロックが日本語、一部が英語
- 例: `describe("顧客作成の成功パターン")`と`describe("Business rule validation")`が混在

**改善案**
- プロジェクト全体で日本語か英語のどちらかに統一すべき
- ビジネス要件を表現する場合は日本語の方が仕様として理解しやすい

### 2. エラーメッセージの詳細度

**問題点**
- `convertLeadToCustomer.test.ts`の一部のテストでエラーメッセージが汎用的
- 例: `expect(result._unsafeUnwrapErr().message).toContain("Invalid input")`

**改善案**
- 具体的なエラー理由を検証するようにする
- 例: `expect(result._unsafeUnwrapErr().cause?.message).toContain("UUIDの形式が無効です")`

### 3. テストデータファクトリの不完全な部分

**問題点**
- `createContactTestData`でcustomerIdが空文字列のデフォルト値
- テスト実行時に必ず上書きが必要

**改善案**
```typescript
export function createContactTestData(
  options: TestFactoryOptions & { customerId: string } // 必須にする
): CreateContactInput {
  // ...
}
```

### 4. boundaryテストでの網羅性

**問題点**
- `createActivity.boundary.test.ts`は非常に詳細だが、他のドメインでboundaryテストが不足
- Customer, Lead, Dealなどの主要ドメインにもboundary testが必要

**改善案**
- 各主要ドメインに対してboundary testファイルを作成
- 特に文字列長、数値範囲、日付範囲の境界値テストを追加

### 5. テストの独立性

**問題点**
- 一部のテストでsetup処理が重複している
- 各テストファイルで同様のユーザー作成、顧客作成コードが繰り返されている

**改善案**
- `testFactories.ts`にもっと高レベルのヘルパー関数を追加
```typescript
export async function setupTestUserWithCustomer(context: Context) {
  // ユーザーと顧客を一度に作成
}
```

### 6. パフォーマンステストの不足

**問題点**
- 大量データ処理のテストが見当たらない
- 例: 1000件のリードを一括処理する場合のテスト

**改善案**
- パフォーマンス専用のテストファイルを追加
- `testUtils.ts`の`measureTestPerformance`を活用

### 7. エッジケースの命名規則

**問題点**
- edge-cases.test.tsファイルが一部のドメインにのみ存在
- ファイル名の付け方に一貫性がない（validation.test.ts、boundary.test.tsなど）

**改善案**
- テストファイルの命名規則をドキュメント化
```
${usecase}.test.ts - 基本テスト
${usecase}.boundary.test.ts - 境界値テスト
${usecase}.edge.test.ts - エッジケーステスト
${usecase}.perf.test.ts - パフォーマンステスト
```

### 8. モックの使用が不十分

**問題点**
- 外部サービス（メール送信、通知送信など）のモックが見当たらない
- 実際のデータベースを使用しているため、テストが遅くなる可能性

**改善案**
- `src/core/adapters/mock/`ディレクトリを活用してモック実装を充実させる
- 外部サービス連携のテストではモックを使用

### 9. テストカバレッジの可視化

**問題点**
- どのコードパスがテストされていないか不明確
- coverageレポートの生成設定が見当たらない

**改善案**
- vitest.config.tsにカバレッジ設定を追加
```typescript
coverage: {
  reporter: ['text', 'html'],
  exclude: ['node_modules', 'test'],
  threshold: {
    branches: 80,
    functions: 80,
    lines: 80
  }
}
```

### 10. 非同期処理のテスト

**問題点**
- タイムアウトやリトライ処理のテストが不足
- 並行処理のテストが見当たらない

**改善案**
- 非同期処理専用のテストを追加
- Promise.allやPromise.raceを使った処理のテスト

## 良い点（参考）

- テストファクトリパターンの採用
- Result型を使用したエラーハンドリングのテスト
- ビジネスロジックに焦点を当てたテストケース名
- setupFreshTestDatabaseによるテスト間の独立性確保
- 日本語でのビジネス要件の記述（一部）
