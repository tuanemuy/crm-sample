# 競合情報記録 テストケース

## 概要
商談における競合他社の情報を記録する機能のテストケース

## 基本機能テスト

### TC001: 競合他社の追加 - 正常パターン
**テストケース名**: 商談に競合他社情報を新規追加する
**説明**: 競合企業の基本情報を登録
**前提条件**: 
- ユーザーがログインしている
- 商談編集権限を持っている
- 対象の商談が存在する
**テストステップ**:
1. 商談詳細画面を開く
2. 「競合情報」タブを選択
3. 「競合追加」ボタンをクリック
4. 競合社名「ABC株式会社」を入力
5. 保存ボタンをクリック
**期待結果**: 
- 競合情報が正常に追加される
- 競合一覧に新しい企業が表示される
- 追加成功メッセージが表示される

### TC002: 競合の強み・弱みの記録 - 正常パターン
**テストケース名**: 競合他社の強みと弱みを詳細記録
**説明**: SWOT分析形式での競合分析情報記録
**前提条件**: 
- 競合他社が登録済み
**テストステップ**:
1. 登録済み競合の詳細を開く
2. 強みフィールドに「価格競争力」「ブランド力」を入力
3. 弱みフィールドに「サポート体制」「導入実績」を入力
4. 保存を実行
**期待結果**: 
- 強み・弱みが保存される
- 競合比較レポートに反映される
- 営業戦略立案に活用可能

### TC003: 提案価格の記録 - 正常パターン
**テストケース名**: 競合他社の提案価格情報を記録
**説明**: 価格競争分析のための金額情報記録
**前提条件**: 
- 競合情報が存在する
**テストステップ**:
1. 競合詳細画面を開く
2. 提案価格に「800,000円」を入力
3. 価格条件「年間契約」を記録
4. 保存を実行
**期待結果**: 
- 価格情報が記録される
- 自社提案との比較が可能
- 価格戦略レポートに反映される

### TC004: 競合ステータスの更新 - 正常パターン
**テストケース名**: 競合他社の競争状況を更新
**説明**: アクティブ、脱落、勝利等のステータス管理
**前提条件**: 
- 複数の競合が登録されている
**テストステップ**:
1. 競合リストから対象を選択
2. ステータスを「アクティブ」から「脱落」に変更
3. 脱落理由を入力
4. 更新を実行
**期待結果**: 
- ステータスが更新される
- 脱落理由が記録される
- 競争相手の数が自動調整される

## 詳細分析テスト

### TC005: 製品比較表の作成 - 分析テスト
**テストケース名**: 自社製品と競合製品の比較表作成
**説明**: 機能、価格、サービスの比較分析
**前提条件**: 
- 製品マスタが設定されている
- 競合製品情報が登録済み
**テストステップ**:
1. 「製品比較」機能を選択
2. 比較項目を設定
3. 競合製品の情報を入力
4. 比較表を生成
**期待結果**: 
- 詳細な比較表が生成される
- 優位性が視覚的に表示される
- 提案資料として出力可能

### TC006: 競合動向の時系列記録 - 分析テスト
**テストケース名**: 競合他社の動向を時系列で記録
**説明**: 提案タイミング、価格変更等の履歴管理
**前提条件**: 
- 時系列記録機能が利用可能
**テストステップ**:
1. 競合詳細から「動向履歴」を選択
2. 日付と動向内容を入力
3. 重要度レベルを設定
4. 記録を保存
**期待結果**: 
- 時系列での動向が記録される
- タイムラインで表示される
- 重要な動向がハイライトされる

## 勝敗分析テスト

### TC007: 受注結果の記録 - 結果テスト
**テストケース名**: 商談の最終結果を競合情報に記録
**説明**: 勝敗とその要因を分析記録
**前提条件**: 
- 商談が完了している（受注/失注）
**テストステップ**:
1. 商談完了後、競合情報を更新
2. 最終結果「自社受注」を記録
3. 勝因「価格優位性」「技術力」を記録
4. 保存を実行
**期待結果**: 
- 勝敗結果が記録される
- 勝因・敗因が分析される
- 今後の戦略に活用される

### TC008: 敗因分析の詳細記録 - 結果テスト
**テストケース名**: 失注時の詳細な敗因分析
**説明**: 競合に負けた理由の詳細分析
**前提条件**: 
- 失注した商談が存在
**テストステップ**:
1. 失注商談の競合情報を開く
2. 敗因「価格差」「機能不足」を詳細記録
3. 改善提案を記録
4. 保存を実行
**期待結果**: 
- 詳細な敗因が記録される
- 改善提案が保存される
- 類似案件の参考情報として活用

## データ管理テスト

### TC011: 競合マスタとの連携 - データテスト
**テストケース名**: 競合企業マスタとの情報連携
**説明**: 既存の競合企業マスタからの情報取得
**前提条件**: 
- 競合企業マスタが整備されている
**テストステップ**:
1. 競合追加時に企業検索を実行
2. マスタから企業を選択
3. 基本情報の自動入力を確認
**期待結果**: 
- マスタ情報が自動入力される
- 重複登録が防止される
- 情報の一元管理が実現

### TC012: 競合情報の一括更新 - データテスト
**テストケース名**: 複数商談の競合情報を一括更新
**説明**: 同一競合の情報変更を全商談に反映
**前提条件**: 
- 同一競合が複数商談に登録されている
**テストステップ**:
1. 競合マスタの情報を更新
2. 「関連商談に反映」を選択
3. 一括更新を実行
**期待結果**: 
- 全関連商談の情報が更新される
- 更新対象商談数が表示される
- 処理結果が報告される

## 異常系テスト

### TC014: 重複競合の検出 - エラーパターン
**テストケース名**: 同一商談に同じ競合を重複登録
**説明**: 重複チェック機能の確認
**前提条件**: 
- 既に登録済みの競合が存在
**テストステップ**:
1. 同じ競合企業を再度追加試行
**期待結果**: 
- 重複警告が表示される
- 既存情報の更新オプションが提供される
- 重複登録は防止される

### TC015: 必須項目の検証 - エラーパターン
**テストケース名**: 競合社名が未入力での保存試行
**説明**: 必須項目の入力検証
**前提条件**: 
- 競合追加画面を表示
**テストステップ**:
1. 競合社名を空欄のまま保存
**期待結果**: 
- エラーメッセージが表示される
- 必須項目が強調表示される
- 保存は実行されない

### TC016: 権限不足での編集 - エラーパターン
**テストケース名**: 編集権限のないユーザーが情報変更
**説明**: アクセス権限チェックの確認
**前提条件**: 
- 参照のみ権限のユーザーでログイン
**テストステップ**:
1. 競合情報の編集を試行
**期待結果**: 
- 編集フィールドが読み取り専用
- 保存ボタンが非活性
- 権限エラーが表示される
